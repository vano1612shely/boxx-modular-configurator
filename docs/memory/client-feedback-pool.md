Замовник BOXX прислав 20 коментарів після перегляду демо. Повний розбір із
посиланнями на файли — у локальному `docs/client-feedback.md` (каталог `/docs` у
`.gitignore`). Гілка `client-feedback-triage`.

**Пул виконано 2026-08-06** — 2, 3, 4, 5, 6, 7, 8, 10, 12, 13, 14, 16, 17, 18 плюс три
внутрішні полагодження, яких замовник не бачив (залипання `moveToTarget`, стори, що
переживали зміну будівлі, застаріла тінь при обертанні меблів). 10 комітів у
`client-feedback-triage`, у main не залито.

**Перевірка 3D тільки через headless Chrome + CDP** — вбудована панель браузера не
фаєрить rAF. Харнес: `scratchpad/cdp.mjs`, r3f-стор дістається через підроблений хук
React DevTools (`__REACT_DEVTOOLS_GLOBAL_HOOK__.onCommitFiberRoot` → containerInfo із
`getState`). Знахідка: **вхід у кімнату втрачає WebGL-контекст у headless навіть на
справжньому GPU** — відтворюється і на незміненому шляху через «+», тож це не регресія;
у звичайному браузері замовник користувався демо без проблем.

**Відклали, з причинами (це рішення клієнта, не мої):**
- **#1 яскравість/кольори і вивіски** — імовірно проблема самої імпортованої glb.
  Повернутись, коли буде інша модель для порівняння; по вивісках клієнт уточнює в
  замовника, чи це фіксований брендинг (тоді запікає моделяр і коду нема) чи дані.
- **#11 стеля/дах у кімнаті** — знято як не варте уваги. Якщо повернемось:
  згенерована кімната вже має стелю з власним `ceilingHidden`, тож це S, а не місяць.
- **#20 email/share** — передача даних для квотації **вже працює** через
  `integration-settings.webhookUrl` + postMessage; бракує лише листа (адаптера
  пошти в Payload немає взагалі) і share-посилання.
- **#9 входи (настил/сходи/пандус/навіс)** — окрема велика задача, планувалась далі.
- **#19** — переформульовано клієнтом: це **не** про орієнтацію меблів, а про
  кімнату «конференц-зал + кухня без перегородки», тобто одна кімната з двома
  зонами і різною фурнітурою в кожній. Робити разом із #9.
- **#15** — клієнт хоче саме **конфігуратор квізу в Payload** (кроки/питання/
  варіанти як дані), не просто редаговані тексти. Окрема велика задача.

**Узгоджені рішення по формі:**
- #14 площа кімнати — поле `areaSqFt` у схемі кімнати, **порожнє = рахується з
  полігона**, заповнене виграє. Без `beforeChange`-хука, щоб ручна правка не
  затиралась і не було застарілих чисел.
- #16 — адмін позначає `recommendedFor` (типи кімнат); користувач бачить два блоки.
  `compatibleRoomTypes` лишається фільтром, `recommendedFor` — розбиттям усередині.
- #12 — додаємо всі три відсутні поля: місткість, орієнтовна ціна, строк.
- #3 — «Move to selected» просто прибирається в режимі перегляду будівлі.
