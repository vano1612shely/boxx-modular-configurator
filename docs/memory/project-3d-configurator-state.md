Проєкт: 3D-конфігуратор будівель (референс — IKEA room designer) для замовника BOXX Modular. Дедлайн делівері веб-конфігуратора: жовтень 2026, go-live листопад 2026, друга регіональна ітерація Q1 2027.

Узгоджені із користувачем рішення (2026-07-18): одна готова glb-модель на кожен розмір будівлі (НЕ секційна збірка); Option A+B (drag/rotate пакетів) одразу; повна система (адмінка+клієнт) без окремого демо-етапу; сховище — локальний диск із перемиканням на S3/R2 через env (`S3_BUCKET`); регіони закладені в схему одразу.

Реалізовано (усі 8 milestone'ів, деталі в README.md): Payload 3.86 + Next 16 моноліт, PostgreSQL у Docker, пайплайн оптимізації glb (gltf-transform: dedup/prune/weld/WebP/meshopt) у hook колекції models, rules-engine (closest size + пороги санвузлів + over-capacity → custom quote), room-focus viewer з auto-hide стін/даху, drag/rotate пакетів з колізіями по footprint, аксесуари по слотах, quote → колекція + webhook + postMessage, iframe embed через query params, адмінський Scene Editor (кастомна вкладка /scene-editor на building-models: меші, кімнати, камери, placements, слоти).

Dev-креденшели адмінки в .env (DEV_ADMIN_EMAIL/PASSWORD). Seed: `pnpm seed` — ідемпотентний, генерує демо-glb процедурно ([[env-quirks-3d-configurator]]).

UX-раунд редактора (2026-07-26, фідбек користувача "дуже незручно"): головні болі — не можна було додати стіну в НАЯВНУ кімнату (пастка "→ Room" створювала нову; тепер контекстні меню мають цілі "Wall in Room N" через onAddBlockFromNodes(scope, paths, roomIndex)), зовнішня+внутрішня обшивки різались окремо (тепер cutDraft.paths[] — одна площина ріже все виділення), сайдбар: блоки кімнат/даху компактними mono-рядками (BlockListRow) + спільний EditorMenuPopup (ui/EditorMenu.tsx) і білдери пунктів (ui/menu-items.ts) для ПКМ у сцені ТА в сайдбарі. Мета користувача: підготовка моделі за ХВИЛИНИ — авто-планувальник стін planRoomWalls (model/auto-room.ts): по полігону кімнати сам планує розрізи на границях (AABB-передбачення частин без сцени, реюз наявних розрізів) і прив'язує обшивки/двері до стін-смуг (WALL_OUT 0.45/WALL_IN 0.08). ВАЖЛИВО: рукомальовані полігони «шумлять» по осях (5–15 см) — Auto walls спершу проганяє rectifyPolygon (толеранс max(0.2, 8% довжини ребра)) і зберігає вирівняний полігон у кімнату; строго діагональні ребра лишаються ручними (skippedEdges). Кнопка «⚡ Auto walls» на картці кімнати + пункт ПКМ. Швидкий флоу: нода підлоги → New room from object → Auto walls → нода стелі → Ceiling in room → дах раз на модель.

Клієнтський баг стін (2026-07-26, пофікшено): «зовнішні зникають, внутрішні ні». Причини: (1) юзерська «стіна» розміром з кімнату (центр=центроїд → facing-дот 0 → ніколи не ховається) з прив'язаною обшивкою; (2) ручні бокси стін не накривали зовнішню обшивку → фрагменти різались шейдером звідусіль; (3) SLALE NO-OP РОЗРІЗИ: збережений розріз, чия площина не перетинає реальну геометрію, рантаймом пропускається, але планувальник вважав шлях спожитим НАЗАВЖДИ → обшивка ставала непланованою. Фікси: планувальник ігнорує розрізи без жодної частини у списку нод (effectiveCuts); заглушки будуються ПО КЛАСТЕРАХ перетинів (CAP_CLUSTER_GAP 0.35), а не одним bbox-квадом (зникли висячі смуги); ring-split у планувальнику (3 розрізи caps=false, явна прив'язка панелей до ребер) — для моделей з суцільним кільцем обшивки (у BOXXPlex-моделі обшивки виявились окремими тонкими панелями на кожну стіну). Анатомія BOXXPlex glb: великі зв'язні вузли 5 (зовнішня оболонка+південь), 38 (внутрішні лайнінги кількох стін), окремі панелі 12/46; полігон юзера може не сягати реальних внутрішніх граней на 15-20 см — не страшно, keep-бокси смуг покривають.

Різання моделі (2026-07-26, рішення користувача — стіни з реальної геометрії): декларативні розрізи sceneConfig.nodeCuts `{id, path, axis x|z, value, capA, capB}` застосовуються при завантаженні в адмінці І клієнті (glb не змінюється). Частини = віртуальні шляхи `path@a`/`path@b` (вкладено `p@a@b`), реєстр живе в root.userData (appliedCutsOf), оригінал ховається з VISIBILITY_LOCK_KEY (інакше diff setHiddenObjects його "воскрешає" — реальний баг, пофікшено). Заглушки зрізу — CAP_COLOR-квади по crossings bbox, патчаться controller.patchMaterial. Ядро: src/shared/three/node-cuts.ts (bisect Sutherland-Hodgman, атрибути через getX — квантизація meshopt). Флоу: ПКМ→Cut→прев'ю площини (снап до координат полігонів кімнат, X/Z осі, Esc)→клік; частини в аутлайнері як "name · A/B"; стіна з виділених нод = union AABB + nodePaths. Автогенерація стін при створенні кімнати ПРИБРАНА (лишилась кнопка Regenerate walls) — два режими співіснують. Клік-цикл по сцені єдиний: блоки + реальні ноди разом.

Зонна система (2026-07-21, рішення користувача — повна заміна mesh-name підходу): кімнати = полігони точок (floorPolygon), стіни/стеля/дах = axis-aligned блоки-об'єми (wallBlocks/ceilingBlocks per room, roofBlocks per building). Рантайм — фрагментний шейдерний кліпінг (src/shared/three/zone-clipping.ts, onBeforeCompile, спільні uniforms). Клієнт: Overview без auto-hide стін (тільки дах/стеля приховані, тогл Ceiling), dollhouse лише для кімнат (ізоляція полігоном + keep wallBlocks, фронтальні блоки ховаються за камерою). Меблі: кламп/колізії/снап по полігону, снап до похилих ребер під їх кутом (entities/building/lib/polygon.ts). Адмін-редактор: малювання полігона точками, drag-створення блоків, ручки resize/move, Client preview (off/building/room). 3D-прев'ю в колекції models (ui-field ModelPreviewField). Реімпорт моделей: pnpm seed + npx tsx scripts/import-boxxplex.ts <шлях до scene.gltf>. Важливо: Show/For НЕ відкладають обчислення inline-props — гвардити індексні доступи optional chaining.
